SOC301B — R Cheatsheet (3): Advanced statistical techniques

How to run them in R, and how to read the output

This is part 3 of the cheatsheet. Part 1 covers programming, part 2 covers statistics (linear and logistic regression). Part 3 covers the advanced techniques we saw in class: data audit, categorical predictors and ANOVA, interactions, mixed models, assumption checks, model selection with AIC, and sensitivity analyses. We spent most of our time on the concepts; this document focuses on how to do it in R.

0. Setup

0.1 Packages

You need to install these packages once, in the console:

install.packages(c("mice", "lmerTest", "car", "performance", "see", "specr"))

Then load them at the top of your .qmd:

library(tidyverse)

Before running any model, check your data for two problems: missing values and outliers. Both can change your results without you noticing.

1.2 Do missing values differ between groups?

A few missing values are not a problem if they are spread randomly. They are a problem if they are concentrated in one group. To check, use the same trick as for a 0/1 variable: the mean of is.na() is the share of missing values. Then compute it within each group, with group_by():

data %>%
  group_by(Institutional_Policy) %>%                                  # one group per policy
  summarise(pct_missing_AI = mean(is.na(Weekly_GenAI_Hours)) * 100,   # share of missing AI hours, in %
            n = n())                                                  # number of students in the group
Institutional_Policy pct_missing_AI n
Allowed 3.490963 4039
Banned 21.852237 961

Missing values on AI use are much more frequent in universities that ban AI. A plausible explanation: when AI is forbidden, some students don’t want to admit how much they use it. This matters because lm() silently deletes every row with a missing value: we would lose a large part of the students from banned universities, and maybe precisely the heaviest users.

✅ “7% of students did not report their AI use. These missing values are not random: they are much more frequent in universities that ban AI.”

1.3 What to do with missing values?

You have two main options.

Option 1: delete the rows with missing values. This is what R does by default. It is fine when there are few missing values, and when they are spread randomly. In all cases, say how many rows you lost.

Option 2: multiple imputation, with the mice package. The idea: replace each missing value by a plausible value, predicted from the other variables. Since we can’t know the true value, we do it several times (for instance 5), with slightly different predicted values each time. We then fit our model on each of the 5 completed datasets, and combine (pool) the 5 results into one.

It works in five steps, which fit nicely in a pipe:

  1. select() the variables used for the imputation (your model’s variables, plus other variables that help predict the missing values);
  2. mice() creates the m completed datasets;
  3. with() fits your model on each of them;
  4. pool() combines the m results;
  5. summary() shows the final result.

Question: do students who use AI more get lower grades, taking into account their grades before the semester?

# Model WITHOUT imputation: R deletes every row with a missing value
model_deleted = lm(Post_Semester_GPA ~ Weekly_GenAI_Hours + Pre_Semester_GPA, data = data)

# Model WITH multiple imputation
model_imputed = data %>%
  # Step 1: keep the variables of the model, plus other variables that can help
  # predict the missing values
  select(Post_Semester_GPA, Weekly_GenAI_Hours, Pre_Semester_GPA,
         Institutional_Policy, Perceived_AI_Dependency,
         Traditional_Study_Hours, Major_Category) %>%
  # mice needs categories to be factors, not text
  mutate(Institutional_Policy = factor(Institutional_Policy),
         Major_Category       = factor(Major_Category)) %>%
  # Step 2: create 5 completed datasets
  # (print = FALSE hides the progress messages; seed = 123 makes the result reproducible)
  mice(m = 5, print = FALSE, seed = 123) %>%
  # Step 3: fit the same model on each of the 5 datasets
  with(lm(Post_Semester_GPA ~ Weekly_GenAI_Hours + Pre_Semester_GPA)) %>%
  # Step 4: combine the 5 results into one
  pool() %>%
  # Step 5: show the final result
  summary()

1.4 Outliers in a distribution

An outlier is an observation very far from the others. The simplest way to spot them is to look at the distribution:

# Boxplot of AI hours (missing values are automatically left out)
ggplot(data, aes(x = Weekly_GenAI_Hours)) +
  geom_boxplot() +
  labs(x = "Weekly hours of AI use") +
  theme_minimal()

The dots on the right are the outliers according to the boxplot rule: more than 1.5 interquartile ranges above the box (see Cheatsheet 2). Another common rule, which we saw in Cheatsheet 1 (section 8.3): an observation is an outlier if it is more than 3 standard deviations away from the mean. To count them:

# Mean and standard deviation of AI hours (na.rm = TRUE: ignore the missing values)
ai_mean = mean(data$Weekly_GenAI_Hours, na.rm = TRUE)
ai_sd   = sd(data$Weekly_GenAI_Hours, na.rm = TRUE)

# Count the students more than 3 standard deviations above or below the mean
data %>%
  filter(Weekly_GenAI_Hours > ai_mean + 3 * ai_sd |
         Weekly_GenAI_Hours < ai_mean - 3 * ai_sd) %>%
  count()
n
97

NB: An outlier is not necessarily an error. A student who uses AI 40 hours a week is unusual, but real. Only remove an observation if you have a good reason to think it’s an error, and always say it.

1.5 Outliers in a regression: Cook’s distance

In a regression, what matters is not whether a point is unusual, but whether it is influential: whether removing it would change the results a lot. Cook’s distance measures this, for each observation.

# Keep only the students with no missing value on the variables of the model
# (so that each row of data_complete matches one Cook's distance)
data_complete = data %>%
  filter(!is.na(Weekly_GenAI_Hours), !is.na(Pre_Semester_GPA))

# Fit the model
model = lm(Post_Semester_GPA ~ Weekly_GenAI_Hours + Pre_Semester_GPA, data = data_complete)

# Add the Cook's distance of each student as a new column
data_complete = data_complete %>%
  mutate(cooks_d = cooks.distance(model))

# How many students are influential (Cook's distance above 4/N)? What is the highest Cook's distance?
data_complete %>%
  summarise(n_influential = sum(cooks_d > 4 / n()),
            max_cooks_d   = max(cooks_d))
n_influential max_cooks_d
206 0.0438739

A Cook’s distance above 1 is usually considered problematic for a single point; 4/N is a stricter rule, which flags more points. You can also plot them:

# Give each student a number (1, 2, 3...), to use as the x-axis
data_complete = data_complete %>%
  mutate(student = row_number())

# One dot per student: its Cook's distance
ggplot(data_complete, aes(x = student, y = cooks_d)) +
  geom_point(alpha = 0.3) +
  geom_hline(yintercept = 4 / nrow(data_complete), linetype = "dashed") + # horizontal line at 4/N
  labs(x = "Student", y = "Cook's distance") +
  theme_minimal()

The dots above the dashed line are the influential students.

The best way to know whether influential points matter is to refit the model without them, and compare:

# Same model, without the influential students
model_without = lm(Post_Semester_GPA ~ Weekly_GenAI_Hours + Pre_Semester_GPA,
                   data = data_complete %>% filter(cooks_d <= 4 / n()))

# Compare the coefficients
coef(model)          # with all students
       (Intercept) Weekly_GenAI_Hours   Pre_Semester_GPA 
        0.35061280        -0.00147554         0.95910434 
coef(model_without)  # without the influential students
       (Intercept) Weekly_GenAI_Hours   Pre_Semester_GPA 
      3.492352e-01      -1.427754e-06       9.573942e-01

✅ “206 observations had a Cook’s distance above 4/N, and none above 1. Removing them changed the slope of AI use from -0.0015 to -0.0000.”

The limit: these coefficients only compare each category to the baseline. None of them answers the global question: “does the use of AI matter at all?”

2.2 With an ANOVA: one global test

The ANOVA answers this global question with a single test, the F test:

# ANOVA table of the same model: one F test for the variable as a whole
anova(model_use)
Df Sum Sq Mean Sq F value Pr(>F)
Primary_Use_Case 4 10410.82 2602.7049 14.89952 0
Residuals 4995 872545.53 174.6838 NA NA

How to read it. The F ratio compares two estimates of the variance of the outcome: one based on the differences between the group means, and one based on the differences within the groups. If the use of AI doesn’t matter, the two should be about the same, and F should be close to 1. The larger F, the stronger the evidence that the group means really differ. The F ratio comes with two degrees of freedom: the number of categories minus 1 (here 4), and roughly the number of observations minus the number of estimated parameters.

✅ “The main use of AI was significantly associated with skill retention (F(4, 4995) = 14.90, p < .001).”

Trap:

❌ “The ANOVA shows that debugging is the best use.”

No: a significant ANOVA only says that some means differ. It says nothing about which ones, or in which direction. Always follow it with the group means, or the coefficients of the lm().

With several predictors. When your model contains other variables, use Anova() from the car package, with type = 2. Each row then tests one variable, taking the others into account:

# A model with two predictors
model_use_2 = lm(Skill_Retention_Score ~ Primary_Use_Case + Weekly_GenAI_Hours, data = data)

# ANOVA table with type 2 tests (note the capital A: this is the Anova() function of the car package)
Anova(model_use_2, type = 2)
Sum Sq Df F value Pr(>F)
Primary_Use_Case 10684.83 4 15.53318 0
Weekly_GenAI_Hours 12047.45 1 70.05645 0
Residuals 798446.53 4643 NA NA

NB: Note the capital A. anova() (base R) computes “type 1” tests, which depend on the order of the variables in the formula. Anova(..., type = 2) doesn’t, which is why we use it as soon as there are several predictors.

So, lm() or ANOVA? Often both: the ANOVA for the global question (“does this variable matter?”), the lm() for the details (“which categories differ, and by how much?”). Say explicitly which one answers your research question.

3. Interaction models

An interaction answers the question: does the effect of one variable depend on another variable? For instance: is AI use related to grades in the same way in universities that allow AI and in those that ban it?

3.1 Look at the data first

# One regression line per policy (color = Institutional_Policy)
ggplot(data, aes(x = Weekly_GenAI_Hours, y = Post_Semester_GPA, color = Institutional_Policy)) +
  geom_point(alpha = 0.15) +
  geom_smooth(method = "lm") +
  labs(x = "Weekly hours of AI use", y = "Post-semester GPA", color = "AI policy") +
  theme_minimal()

The two lines don’t have the same slope: that is what an interaction looks like.

3.2 Run the model

The interaction is written with *. x * z means: the effect of x, the effect of z, and their interaction (x:z).

# Interaction model: the * includes both variables AND their interaction
model_inter = lm(Post_Semester_GPA ~ Weekly_GenAI_Hours * Institutional_Policy, data = data)
summary(model_inter)

3.3 Read the coefficients

This is the tricky part. With an interaction, each coefficient only describes one specific situation:

  • (Intercept): the predicted GPA of a student who uses AI 0 hours, in the baseline group (universities that allow AI).
  • Weekly_GenAI_Hours: the slope of AI use in the baseline group only (universities that allow AI). It is not the effect of AI use for everyone.
  • Institutional_PolicyBanned: the difference in GPA between banned and allowed universities, for students who use AI 0 hours.
  • Weekly_GenAI_Hours:Institutional_PolicyBanned: the interaction. It is the difference between the two slopes: how much more (or less) the slope of AI use is in banned universities, compared to allowed ones.

To get the slope in banned universities, add the slope of the baseline and the interaction:

# Slope of AI use where AI is allowed (the baseline): the coefficient of Weekly_GenAI_Hours
slope_allowed = coef(model_inter)["Weekly_GenAI_Hours"]

# Slope of AI use where AI is banned: the baseline slope + the interaction
slope_banned = coef(model_inter)["Weekly_GenAI_Hours"] +
               coef(model_inter)["Weekly_GenAI_Hours:Institutional_PolicyBanned"]

How to say it:

✅ “In universities that allow AI, the number of hours of AI use is not related to GPA (b = -0.0002). Traps:

❌ “The coefficient of Weekly_GenAI_Hours shows that AI use has no effect on grades.”

No: in an interaction model, it is the effect in the baseline group only (here, universities that allow AI).

❌ “The p-value of Weekly_GenAI_Hours tells me whether AI use matters in banned universities.”

No: it tests the slope in the baseline group. To test the slope in the other group, change the baseline with relevel() and rerun the model.

NB: Interaction between two continuous variables (e.g. Weekly_GenAI_Hours * Traditional_Study_Hours): the interaction coefficient is how much the slope of one variable changes when the other increases by one unit.

4. Linear mixed models

4.1 Why: non-independent observations

A linear regression assumes that observations are independent: each one brings new, separate information. This is violated when observations are grouped: several answers from the same participant, students from the same class, songs from the same playlist. Observations from the same group tend to be similar, and a regular lm() acts as if it had more information than it really has.

A linear mixed model fixes this, by telling the model which observations belong to the same group. We use the lmerTest package: it fits the model with lme4, and adds p-values to the output.

The example. Our AI dataset has no such grouping, so we switch to the Spotify dataset. Songs are grouped in playlists: songs from the same playlist share the same audience, so their popularity tends to be similar. Question: are happier songs more popular, when we compare songs within the same playlist?

# Load the Spotify dataset (spotify_songs.csv must be in the same folder)
songs = read.csv("spotify_songs.csv")

4.2 Random intercept

A random intercept allows each group (here, each playlist) to have its own average level of the outcome. The model then compares each song to its playlist’s average, rather than to all other songs. The syntax: lmer() instead of lm(), and + (1 | group) in the formula (“one intercept per group”).

# Regular regression: treats all songs as independent
model_lm = lm(track_popularity ~ valence, data = songs)

# Mixed model: one random intercept per playlist
model_lmm = lmer(track_popularity ~ valence + (1 | playlist_id), data = songs)

How to read it. The output has two parts.

The fixed effects table reads like a regular regression table: estimate, standard error, degrees of freedom (estimated with Satterthwaite’s method, which is why they are not whole numbers), t value, and p-value. Compare the slope of valence with the one of the regular regression:

# Coefficients of the regular regression
coef(model_lm)
(Intercept)     valence 
  40.658927    3.561091

In the regular regression, which compares all songs to each other, the slope of valence is 3.56. In the mixed model, which compares songs within their playlist, it is only 0.92 (line valence of the fixed effects). Much of the apparent effect of valence came from differences between playlists.

The random effects table shows two variances. The variance of playlist_id (Intercept) (here 240) is how much the playlists differ from each other in average popularity. The Residual variance (here 373) is what is left within playlists. Their share tells you how important the grouping is. You can compute it by hand: 240 / (240 + 373) = 0.39. So 39% of the variation left unexplained by valence is due to differences between playlists.

✅ “Comparing songs within the same playlist (random intercept by playlist), going from the saddest to the happiest possible song is associated with 0.92 points of popularity (p = 0.087). Differences between playlists account for 39% of the variance not explained by valence.”

model_lmm_slope = lmer(track_popularity ~ valence + (1 + valence | playlist_id), data = songs)

When to use what.

  • Random intercept: as soon as your observations are grouped, and the grouping variable has many levels (participants, playlists, schools…). If it has very few levels (e.g. 2 experimenters, 3 countries), don’t use a random effect: add it as a regular predictor instead.

NB: If you get a message about a singular fit, one of your random effects probably accounts for almost no variance. You can remove it. If you get a message that the model failed to converge, try another optimizer: add control = lmerControl(optimizer = "bobyqa") inside lmer().

5. Checking the assumptions of a linear model

5.1 The error term

A linear model does not say that all observations sit exactly on the line. With one predictor, the full model is:

\[Y_i = \beta_0 + \beta_1 X_i + \epsilon_i \qquad \epsilon \sim N(0, \sigma^2)\]

The first part says: the value of observation \(i\) is the intercept, plus the slope times \(X_i\), plus an error term \(\epsilon_i\). The error term stands for everything that determines \(Y\) but is not in the model. We can’t know its value for a given observation.

The second part says what we assume about these errors:

  • Normality: they come from a normal distribution with a mean of 0. Some points are above the line, some below, with no systematic direction; most errors are small, and large errors are rare.
  • Homoskedasticity: they all have the same variance \(\sigma^2\). The spread of the errors does not change along the predictor.

We never see the errors, but we see the residuals: the observed value minus the value predicted by the model. The residuals are the observable version of the errors, so we check the assumptions on them. If an assumption is badly violated, the estimates and p-values can be misleading.

Example. Do students who feel more dependent on AI actually use it more?

# Keep only the students with no missing value on AI hours
# (as in 1.5: so that each row of data_check matches one residual)
data_check = data %>%
  filter(!is.na(Weekly_GenAI_Hours))

# Fit the model
model_check = lm(Weekly_GenAI_Hours ~ Perceived_AI_Dependency, data = data_check)

# Add the residual of each student as a new column
# residuals(): observed value minus predicted value
data_check = data_check %>%
  mutate(residual = residuals(model_check))

5.2 Normality: the distribution of the residuals

# Histogram of the residuals
ggplot(data_check, aes(x = residual)) +
  geom_histogram(bins = 50) +
  labs(x = "Residuals (hours of AI use)", y = "Number of students") +
  theme_minimal()

How to read it. You want a roughly symmetric, bell-shaped distribution, centered on 0. Here, the distribution has a long tail on the right (positive skew): some students use AI more than 25 hours more than predicted, but nobody uses it more than about 16 hours less than predicted. This makes sense: you can’t use AI less than 0 hours.

Don’t use normality tests. Some courses teach statistical tests that tell you whether the residuals are “significantly” different from a normal distribution. Avoid them. Whether they are significant depends mostly on the sample size: with a small sample, they miss even dramatic deviations; with a large sample, they flag even tiny, harmless ones. No real data is exactly normal, so with enough observations the test will always be significant. Look at the histogram instead, and ask yourself whether the asymmetry is marked.

5.3 Homoskedasticity: the spread of the residuals

Plot the residuals against the predictor:

# Residuals (y-axis) against the predictor (x-axis)
ggplot(data_check, aes(x = Perceived_AI_Dependency, y = residual)) +
  geom_point(alpha = 0.1) +
  geom_hline(yintercept = 0, linetype = "dashed") + # horizontal line at 0
  labs(x = "Perceived AI dependency (1-10)", y = "Residuals") +
  theme_minimal()

5.5 What to do: transformations

If the assumptions are badly violated, the simplest solution is to transform a variable. A heavier solution is to use another kind of model (e.g. a logistic regression for a binary outcome, see Cheatsheet 2).

Problem Transformation
Residuals skewed to the right, and/or more spread at high values Log of the outcome: log(y)
Residuals skewed to the left, and/or more spread at low values Reverse, then log: log(max(y) + 1 - y). Careful: high values become low values
The relationship between X and Y is not a straight line Log of the predictor: y ~ log(x)

log() is the natural logarithm. It only works on positive numbers: if your variable contains zeros, add a constant first, e.g. log(y + 1).

Our residuals are skewed to the right, with more spread at high values, so we take the log of AI hours (+1, because some students use AI 0 hours):

model_log = lm(log(Weekly_GenAI_Hours + 1) ~ Perceived_AI_Dependency, data = data_check)

6. Model selection with AIC

6.1 What AIC is

The AIC (Akaike Information Criterion) compares several models of the same outcome. It is the sum of two terms: one measures how well the model fits the data (better fit → lower AIC), the other is a penalty for the number of parameters (more complex model → higher AIC). A more complex model only wins if it explains enough additional variation to pay for its extra complexity. This is what protects us from overfitting.

The lower the AIC, the better the model. The AIC has no meaning on its own: only the differences between models matter. As a rule of thumb, models within 2 points of each other are about equally well supported.

AIC is especially useful to compare several non-null hypotheses, when the classic p-value can’t help because all of them are significant.

6.2 Example: three hypotheses about AI use and skill retention

Question: how is AI use related to skill retention? Three hypotheses:

  • Linear: each additional hour of AI use reduces retention by the same amount.
  • Logarithmic: the first hours of AI use matter most, then the effect flattens out.
  • Threshold: moderate use is harmless; only heavy use, here more than 20 hours a week (about half of a full-time study week), is associated with lower retention.

Plus a null model, with no effect of AI use at all.

Rule 1: all models must be fitted on exactly the same data. Otherwise their AICs are not comparable. So we first remove the rows with missing values on the variables we use:

data_aic = data %>%
  filter(!is.na(Weekly_GenAI_Hours)) %>%            # same data for all models
  mutate(heavy_use = Weekly_GenAI_Hours > 20)       # TRUE for heavy users, FALSE for the others
# Linear hypothesis: retention changes by the same amount for each hour of AI use
m_linear = lm(Skill_Retention_Score ~ Weekly_GenAI_Hours, data = data_aic)

# Logarithmic hypothesis: the first hours matter most
# (+1 because the log of 0 doesn't exist, and some students use AI 0 hours)
m_log = lm(Skill_Retention_Score ~ log(Weekly_GenAI_Hours + 1), data = data_aic)

# Threshold hypothesis: only heavy users (more than 20 hours a week) differ
m_threshold = lm(Skill_Retention_Score ~ heavy_use, data = data_aic)

# Null hypothesis: no effect of AI use ("~ 1" means: no predictor, only an intercept)
m_null = lm(Skill_Retention_Score ~ 1, data = data_aic)

# AIC of the four models
AIC(m_linear, m_log, m_threshold, m_null)
df AIC
m_linear 3 37184.92
m_log 3 37233.24
m_threshold 3 37155.38
m_null 2 37243.37

6.3 Differences and AIC weights

To read the results more easily, compute the difference between each model and the best one (delta), and the AIC weight of each model. The AIC weight can be read as the probability that this model is the best of the set:

# A small table with the AIC of each model
aic_table = data.frame(model = c("linear", "log", "threshold", "null"),
                       AIC   = c(AIC(m_linear), AIC(m_log), AIC(m_threshold), AIC(m_null)))

aic_table = aic_table %>%
  mutate(delta  = AIC - min(AIC),                                 # difference with the best model
         weight = exp(-0.5 * delta) / sum(exp(-0.5 * delta))) %>% # AIC weight (standard formula)
  arrange(AIC)                                                    # best model first

aic_table %>% kable(digits = 3)
model AIC delta weight
threshold 37155.38 0.000 1
linear 37184.92 29.535 0
log 37233.24 77.854 0
null 37243.37 87.986 0

✅ “The threshold model had the lowest AIC (AIC weight = 1.00), 30 points below the next best model. The data support the hypothesis that only heavy AI use (more than 20 hours a week) is associated with lower skill retention.”

A plot helps to understand why. geom_smooth() without method = "lm" draws a flexible curve that follows the data:

ggplot(data_aic, aes(x = Weekly_GenAI_Hours, y = Skill_Retention_Score)) +
  geom_point(alpha = 0.1) +
  geom_smooth() +                                    # flexible curve that follows the data
  geom_vline(xintercept = 20, linetype = "dashed") + # vertical dashed line at 20 hours
  labs(x = "Weekly hours of AI use", y = "Skill retention score") +
  theme_minimal()

Retention is flat up to about 20 hours a week, then drops: a threshold, not a straight line.

Traps:

❌ Choosing the threshold after looking at the data.

If you try 10, 15, 20 and 25 hours and keep the one with the best AIC, you have made the data fit your hypothesis. The threshold must be justified before looking at the results.

❌ Comparing models fitted on different data.

If one model uses a variable with missing values, R drops these rows for that model only, and the AICs are no longer comparable.

NB: For mixed models, fit the models with REML = FALSE before comparing their AIC.

NB: The MuMIn package (used in the textbook) computes the deltas and weights for you: MuMIn::model.sel(m_linear, m_log, m_threshold, m_null).

7. Sensitivity analyses with specr

7.1 The idea

In any analysis, you make many decisions that could have been made differently: which control variables, which transformation, which sub-sample… A specification curve analysis reruns the analysis with every combination of these decisions, and shows how the result changes. If the conclusion holds across most specifications, it is robust. If it depends on one particular decision, you need to know it.

7.2 Set up the specifications

Question: is the link between AI use and grades robust? We vary three decisions:

  • x (the predictor): AI hours as they are, or log-transformed;
  • controls: none, previous GPA, study hours without AI, or both;
  • subsets: all students, only universities that allow AI, or only those that ban it.
specs = setup(data = data,
              y = "Post_Semester_GPA",                                     # the outcome
              x = c("Weekly_GenAI_Hours", "log(Weekly_GenAI_Hours + 1)"),  # the possible predictors
              model = "lm",                                                # the type of model
              controls = c("Pre_Semester_GPA", "Traditional_Study_Hours"), # the possible controls
              subsets = list(Institutional_Policy = c("Allowed", "Banned"))) # the possible sub-samples
